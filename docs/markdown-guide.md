# 마크다운으로 글 쓰기

노션 토큰 없이 바로 쓸 수 있는 방식입니다. 글이 저장소에 파일로 남아 수정 이력이 그대로 보관됩니다.

## 파일 위치와 이름

`content/posts/` 안에 `.md` 파일을 만듭니다. 파일 이름은 자유지만 슬러그와 맞춰두면 찾기 쉽습니다.

```
content/posts/산재-처리하면-보험료-오를까요.md
```

## 파일 구조

맨 위 `---` 사이가 속성 영역이고, 그 아래가 본문입니다. 속성 이름은 노션과 똑같아서 나중에 노션으로 옮겨도 그대로 쓸 수 있습니다.

```markdown
---
제목: 산재 처리하면 보험료 오를까요
슬러그: 산재-처리하면-보험료-오를까요
요약: 산재를 신청해도 대부분의 중소 사업장은 보험료가 오르지 않습니다. 개별실적요율이 30인 이상 사업장에만 적용되기 때문입니다.
카테고리: 산업재해
태그: [중소기업, 사례]
상태: 발행
노출: true
발행일: 2026-07-30
최종수정일: 2026-07-30
작성자: 홍길동
작성자직함: 공인노무사
근거법령: 고용보험 및 산업재해보상보험의 보험료징수 등에 관한 법률 제15조
근거법령링크: https://www.law.go.kr/
CTA유형: 무료진단
---

여기부터 본문입니다.
```

`상태`가 `발행`이고 `노출`이 `true`인 글만 사이트에 나갑니다. 나머지는 파일이 있어도 빌드에서 제외됩니다.

## 제목 단계

노션과 동일하게 한 칸씩 내려갑니다. 글 제목이 이미 h1이라 본문에는 h1을 만들지 않습니다.

| 마크다운에서 쓰는 것 | 실제 HTML | 용도 |
|---|---|---|
| `#` | `<h2>` | 글의 주요 섹션입니다. **3개 이상 필요합니다.** |
| `##` | `<h3>` | 섹션 안의 세부 항목입니다. |
| `###` | `<h4>` | 더 잘게 나눌 때만 씁니다. |

## 첫 문단

`요약`을 비우면 첫 문단이 검색결과 설명문이 됩니다. 인사말이 아니라 결론을 먼저 씁니다.

```markdown
쓰지 않습니다 → 안녕하세요, 노무법인 도원입니다. 오늘은 산재보험료에 대해 알아보겠습니다.

이렇게 씁니다 → 산재를 신청해도 대부분의 중소 사업장은 보험료가 오르지 않습니다.
                개별실적요율은 상시근로자 30인 이상 사업장에만 적용되기 때문입니다.
```

## FAQ

`# 자주 묻는 질문` 섹션을 만들고 그 아래에 `##`로 질문을 적으면, 질문과 답변이 FAQ 구조화 데이터로 자동 변환됩니다.

```markdown
# 자주 묻는 질문

## 산재 처리하면 보험료가 얼마나 오르나요?

상시근로자 30인 미만 사업장은 개별실적요율 적용 대상이 아니라 오르지 않습니다.

## 공상처리하면 신고하지 않아도 되나요?

아닙니다. 3일 이상 휴업이 필요한 재해라면 산업재해조사표를 제출해야 합니다.
```

## 그 밖의 서식

표, 목록, 인용, 링크, 이미지 모두 일반 마크다운 문법 그대로 쓰면 됩니다.

```markdown
| 구분 | 내용 |
| --- | --- |
| 30인 미만 | 적용되지 않습니다 |

- 목록 항목
1. 번호 목록

> 인용문은 강조 박스로 나옵니다.

[링크](https://www.law.go.kr/)
![이미지 설명](https://dowonhr.com/images/example.png)
```

외부 링크는 자동으로 새 탭에서 열리도록 처리됩니다.

## 발행 절차

1. `content/posts/`에 `.md` 파일을 만들고 `상태: 초안`으로 씁니다.
2. 점검기를 돌립니다.
   ```bash
   npm run seo:check -- 초안
   ```
3. 지적된 항목을 고치고 `상태: 발행`으로 바꿉니다.
4. 커밋해서 GitHub에 올립니다. Netlify가 자동으로 재배포합니다.
   ```bash
   git add content/posts
   git commit -m "글 발행: 산재 처리하면 보험료 오를까요"
   git push
   ```

## GitHub 웹에서 바로 쓰기

터미널이 익숙하지 않다면 GitHub 웹사이트에서도 됩니다. 저장소 → `content/posts` 폴더 → `Add file` → `Create new file`로 들어가 파일 이름과 내용을 넣고 `Commit changes`를 누르면 Netlify가 알아서 배포합니다.

## 나중에 노션으로 옮기려면

속성 이름이 같아서 옮기기 쉽습니다. `.env`에 `NOTION_TOKEN`과 `NOTION_DATABASE_ID`를 채우기만 하면 코드가 자동으로 노션을 읽습니다. 마크다운 파일은 그대로 두어도 되고 지워도 됩니다. 노션 설정이 있으면 노션이 우선합니다.

## CTA 유형 고르기

글 속성의 `CTA유형`으로 글 하단 버튼을 고릅니다.

| 값 | 동작 | 언제 쓰나 |
|---|---|---|
| `채팅상담` (기본) | 페이지 이동 없이 그 자리에서 채널톡 상담창이 열립니다. 글 제목이 첫 메시지에 자동으로 들어갑니다. | 대부분의 글에 권장합니다. 홈페이지로 한 번 더 보내지 않아 이탈이 적습니다. |
| `무료진단` | 홈페이지의 진단 신청 페이지로 이동합니다. | 진단 상품과 직접 연결되는 글일 때 씁니다. |
| `체크리스트` | 자료 다운로드 페이지로 이동합니다. | 실무 자료를 미끼로 리드를 받을 때 씁니다. |
| `상담` | 상담 신청 페이지로 이동합니다. | |
| `없음` | 버튼을 넣지 않습니다. | 회사 소식이나 후기 글에 씁니다. |

### 문의가 어느 글에서 왔는지 확인하는 법

채널톡 상담이 열리면 방문자 프로필에 아래 값이 자동으로 기록됩니다.

- `유입글` : 글 제목
- `유입글카테고리` : 카테고리
- `유입글주소` : 글 URL
- `유입채널` : `자체블로그`

채널톡 상담 목록에서 이 값을 보면 어떤 글이 문의를 만들어내는지 바로 알 수 있습니다.

> 참고로 링크형 CTA에는 일부러 `utm_` 파라미터를 붙이지 않았습니다. 채널톡은 UTM을 마지막 값으로 덮어쓰기 때문에, 내부 링크에 utm을 달면 구글 검색 같은 원래 유입 출처가 지워집니다. 대신 `from=blog&post=슬러그` 형태로 표시합니다.
